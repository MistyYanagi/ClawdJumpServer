# 4A 安全规范

4A = 账号（Account）、认证（Authentication）、授权（Authorization）、审计（Audit）。每条要求都对应 `crates/cjs-tests/tests/conformance_4a.rs` 中同编号的测试。

## 账号

**A1 注册令牌一次性且有范围。** 令牌由 sysadmin（设备）或 agent 负责人（自己的 agent）签发，有效期 60 秒到 30 天，绑定类型（agent / device）和名称；兑换是原子操作，重用、过期、类型不符都会被拒绝。库里只存 `sha256(secret)`。没有令牌的未知公钥无法连接，且被审计（`gateway.reject`）。

**A2 禁用立即生效。** 禁用 agent、禁用或使其负责人账号过期、禁用设备，都会立即断开现有连接并阻止重连。agent 负责人可以禁用自己的 agent，但只有 sysadmin 能重新启用。

## 认证

**A3 人员登录 = 口令 + TOTP。** 口令用 argon2id 存储，最短 12 字符。TOTP 允许 ±1 个时间步，同一时间步的验证码不能重用。连续 5 次失败锁定 15 分钟；每个来源地址 15 分钟内最多 20 次失败。未知用户与错误口令返回相同结果，且做等时校验。每次成功与失败都写审计。

**A4 Web 会话。** 会话 Cookie：随机 32 字节、`HttpOnly`、`SameSite=Strict`、`Secure`，库里只存哈希；空闲 30 分钟、最长 12 小时。所有修改请求必须带 `X-CSRF-Token`，带跨站 `Origin` 的请求被拒绝。全部响应带严格 CSP（不允许内联脚本）、`X-Frame-Options: DENY`、`nosniff`、`no-referrer`、HSTS。

机器身份（agent / 设备）是 Noise X25519 静态密钥，握手时双向认证，客户端钉住服务端公钥；握手带时间戳与随机数防重放。

## 授权

**A5 默认拒绝，最小权限。** 没有授权就没有访问。授权规则限定：主体（agent 或 agent 组）、目标（设备、设备组或服务端出口）、动作（shell、exec、file_read、file_write、forward_local、forward_remote、egress）、项目根目录、时间窗、生效与过期时间、网络目标、并发会话上限。未知设备与无权访问的设备返回相同的拒绝；设备列表只显示有权使用的设备。长连接上的每条流都会被周期性重新决策。

**A6 职责分离。** sysadmin：账号、资产、组、设备注册。secadmin：授权、全权限审批、终止会话。auditor：只读审计与录像。secadmin 与 auditor 不能由同一账号兼任；任何人都不能修改自己的角色或状态。

**A7 全权限（双人规则）。** 解除项目目录监狱和沙箱需要提出申请（附理由），由另一名 secadmin 批准；申请人与 agent 负责人都不能批准；最长 8 小时；可随时撤销，撤销后正在进行的会话立即终止。全权限期间的所有事件在审计中高亮。

**A8 设备独立校验。** 设备对每条流单独校验 Ed25519 能力令牌：签名、设备、连接、流、动作、网络目标、有效期（TTL ≤ 60 秒）、防重放。中继被绕过或被攻破也无法扩权。

**A9 监狱与沙箱。** 文件访问用 cap-std 在项目根之下解析（拒绝 `..`、越界符号链接、UNC/设备路径、备用数据流、保留设备名）。shell 与命令运行在操作系统沙箱中，只能写项目根和私有临时目录（Linux Landlock + `no_new_privs`；macOS sandbox-exec；Windows AppContainer + Job Object）。沙箱不可用时拒绝运行（`sandbox_unavailable`）。环境变量使用白名单，`LD_*`、`DYLD_*`、`GLIBC_TUNABLES`、`MALLOC_*` 一律拒绝。出口访问在 DNS 解析后再校验地址（私网、环回、链路本地、元数据地址需要规则以 IP 明确列出），并只连接已校验的地址。

## 审计

**A10 失败即拒绝。** 认证、授权决策、会话开始、管理变更都必须先写入审计；写入失败时操作被拒绝（`audit_failure`）。终端录像写入失败同样会终止会话。

**A11 防篡改。** 每条事件存储被哈希的原始 JSON，`hash_n = BLAKE3(hash_{n-1} || body_n)`；每 100 条、每分钟（有新事件时）以及关机时用 Ed25519 签名检查点。服务端启动时校验整条链，校验失败拒绝启动。审计员可以导出 JSON Lines 并离线校验。会话录像的 SHA-256 记录在 `session.end` 事件中。审计员查询、导出、观看录像本身也会被审计。

## 已知限制

- Windows AppContainer 和 macOS sandbox-exec 依赖 CI 上的实际运行验证；Windows 沙箱内的进程没有网络。
- 经设备 `forward_local` 时只校验名称规则（目的就是访问内网服务），不做解析后地址校验；`egress` 两种出口都做。
- 审计日志若连同全部检查点一起被截断，自身无法发现，需要定期把头部哈希导出到外部存档。
- 录像会记录输入（包括在终端里输入的口令）；这是堡垒机的通常做法，审计员访问录像会被审计。
