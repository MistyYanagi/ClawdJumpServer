# 4A 安全规范

4A = 账号（Account）、认证（Authentication）、授权（Authorization）、审计（Audit）。每条要求都对应 `crates/cjs-tests/tests/conformance_4a.rs` 中同编号的测试。

## 账号

**A1 注册令牌一次性且有范围。** 令牌由 sysadmin（设备）或 agent 负责人（自己的 agent）签发，有效期 60 秒到 30 天，绑定类型（agent / device）和名称；兑换是原子操作：消耗令牌、创建 agent / 设备、写入 `enroll.*` 成功审计在同一个事务里提交，名称冲突等失败时令牌不被消耗、也不记成功审计。重用、过期、类型不符都会被拒绝。库里只存 `sha256(secret)`。没有令牌的未知公钥无法连接，且被审计（`gateway.reject`）。已登记或已吊销的公钥不能再次注册。

**A2 禁用立即生效。** 禁用 agent、禁用或使其负责人账号过期、禁用设备，都会立即断开现有连接并阻止重连。agent 负责人可以禁用自己的 agent，但只有 sysadmin 能重新启用；被禁用的 agent 只有 sysadmin 能删除，删除被禁用的 agent / 设备时其公钥进入吊销列表，不能用新令牌重新注册。

## 认证

**A3 人员登录 = 口令 + TOTP。** 口令用 argon2id 存储，最短 12 字符。TOTP 允许 ±1 个时间步，同一时间步的验证码不能重用（时间步以条件 SQL `last_totp_step < ?` 原子更新，并发请求也只有一个成功）。连续 5 次失败锁定 15 分钟；每个来源地址 15 分钟内最多 20 次失败。两种计数都在校验口令**之前**预占名额，并发猜测也不能超出上限。未知、禁用、过期、锁定的账号与错误口令返回同一个 `invalid credentials`（401），且都做一次 argon2 校验以等时；真实原因只写入审计。登录与改口令只更新各自的列（条件 SQL），不会用旧快照覆盖管理员同时做的禁用或重置。修改口令同样要求口令 + TOTP，失败返回统一错误、计入锁定并写审计（`auth.password_change` denied）。`--trust-forwarded-for` 时 API 取 `X-Forwarded-For` 最右侧（由可信代理追加）的地址。

**A4 Web 会话。** 会话 Cookie：随机 32 字节、`HttpOnly`、`SameSite=Strict`、`Secure`，启用 TLS 时名为 `__Host-cjs_session`（无 TLS 时为 `cjs_session`），库里只存哈希；空闲 30 分钟、最长 12 小时，过期记录在登录时清理。登录锁定只阻止新的登录，不结束已有会话；禁用和过期会立即结束会话。所有修改请求必须带 `X-CSRF-Token`，带跨站 `Origin` 的请求被拒绝。全部响应带严格 CSP（不允许内联脚本）、`X-Frame-Options: DENY`、`nosniff`、`no-referrer`、HSTS。

机器身份（agent / 设备）是 Noise X25519 静态密钥，握手时双向认证，客户端钉住服务端公钥；握手带时间戳与随机数防重放。

## 授权

**A5 默认拒绝，最小权限。** 没有授权就没有访问。授权规则限定：主体（agent 或 agent 组）、目标（设备、设备组或服务端出口）、动作（shell、exec、file_read、file_write、forward_local、forward_remote、egress）、项目根目录、时间窗、生效与过期时间、网络目标、并发会话上限。未知设备与无权访问的设备返回相同的拒绝；设备列表只显示有权使用的设备。长连接上的每条流都会被周期性重新决策。

**A6 职责分离。** sysadmin：账号、资产、组、设备注册。secadmin：授权、全权限审批、终止会话。auditor：只读审计与录像。secadmin 与 auditor 不能由同一账号兼任；任何人都不能修改自己的角色、状态或过期时间。

经 API 授予任何角色（sysadmin、secadmin、auditor）——创建用户时或修改用户时——都只生成待审批的角色变更（`/api/v1/role-changes`），需由**另一名** secadmin（不是申请人，也不是被授予者）批准后才生效；批准时用户的角色必须仍与申请时一致。只移除角色的变更立即生效。申请、批准、驳回都写审计并高亮。持有任何角色的用户的口令与 TOTP 不能通过 API 重置，只能在服务器本机用 `cjs-server reset-user` 重置。服务器本机的 `cjs-server user-add / user-role / reset-user` 由主机控制者执行，可直接分配角色（用于只有一个初始管理员时的引导），同样写审计（actor `system:cli`）。最后一名有效的 secadmin 和最后一名有效的 auditor 不能被禁用、设置过期或去掉该角色。

没有管理角色的用户只能看到其 agent 有授权的设备（不含公钥），以及自己或自己 agent 所在的组。

**A7 全权限（双人规则）。** 解除项目目录监狱和沙箱需要提出申请（附理由），由另一名 secadmin 批准；申请人与 agent 负责人都不能批准；最长 8 小时；可随时撤销，撤销后正在进行的会话立即终止。全权限期间的所有事件在审计中高亮。

**A8 设备独立校验。** 设备对每条流单独校验 Ed25519 能力令牌：签名、设备、连接、流、动作、网络目标、有效期（TTL ≤ 60 秒）、防重放。中继被绕过或被攻破也无法扩权。

**A9 监狱与沙箱。** 文件访问用 cap-std 在项目根之下解析（拒绝 `..`、越界符号链接、UNC/设备路径、备用数据流、保留设备名）。shell 与命令运行在操作系统沙箱中，只能写项目根和私有临时目录（Linux Landlock + `no_new_privs`；macOS sandbox-exec；Windows AppContainer + Job Object）。沙箱不可用时拒绝运行（`sandbox_unavailable`）。环境变量使用白名单，`LD_*`、`DYLD_*`、`GLIBC_TUNABLES`、`MALLOC_*` 一律拒绝。出口访问在 DNS 解析后再校验地址（私网、环回、链路本地、元数据地址需要规则以 IP 明确列出），并只连接已校验的地址。

## 审计

**A10 失败即拒绝。** 认证、授权决策、会话开始、管理变更都必须先写入审计；写入失败时操作被拒绝（`audit_failure`）。终端录像写入失败同样会终止会话。

**A11 防篡改。** 每条事件存储被哈希的原始 JSON，`hash_n = BLAKE3(hash_{n-1} || body_n)`；每 100 条、每分钟（有新事件时）以及关机时用 Ed25519 签名检查点。服务端启动时校验整条链，校验失败拒绝启动。审计员可以导出 JSON Lines 并离线校验。会话录像的 SHA-256 记录在 `session.end` 事件中。审计员查询、导出、观看录像本身也会被审计。

## 已知限制

- Windows AppContainer 和 macOS sandbox-exec 依赖 CI 上的实际运行验证；Windows 沙箱内的进程没有网络。
- 经设备 `forward_local` 时只校验名称规则（目的就是访问内网服务），不做解析后地址校验；`egress` 两种出口都做。
- 审计日志若连同全部检查点一起被截断，自身无法发现，需要定期把头部哈希导出到外部存档。
- 通过 API 创建用户时，sysadmin 会拿到初始口令和 TOTP 密钥；批准该用户角色的 secadmin 应在线下确认使用者本人，并让其先修改口令。
- 网关（agent / 设备连接）记录的来源地址仍由 `cjs-transport` 的 `peer_addr` 取 `X-Forwarded-For` 第一项，待传输层修正为最右项。
- 录像会记录输入（包括在终端里输入的口令）；这是堡垒机的通常做法，审计员访问录像会被审计。
